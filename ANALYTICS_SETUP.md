# DATA C0RE — Analytics setup

## Goal

Measure real website traffic and acquisition sources without changing every existing external link.

The implementation uses Google Analytics 4 only after explicit opt-in. It relies on GA4's normal source / medium attribution when the browser provides a referrer, and adds a best-effort `traffic_origin_hint` event for campaign parameters, referrer host and identifiable in-app browsers.

## Important attribution limit

No analytics system can reliably recover a source that the browser or app does not send.

Examples that may arrive as direct / unknown traffic:

- many email clients;
- Discord and other messaging apps;
- some mobile social-app handoffs;
- PDFs, documents, bookmarks and copied URLs;
- privacy tools that strip referrers.

UTM-tagged links remain the only deterministic way to identify those sources. Existing links do not need to be changed for normal referrer attribution.

## Privacy model

- GA4 is disabled until a valid measurement ID is configured.
- Consent mode is **basic**: the Google tag is not loaded before analytics opt-in.
- `analytics_storage` defaults to denied.
- all advertising consent states remain denied;
- Google Signals are disabled;
- ad-personalization signals are disabled;
- consent acceptance and refusal are both stored for 180 days;
- visitors can reopen **Analytics settings** at any time and change their choice;
- withdrawing consent removes `_ga*` first-party cookies and reloads the page so the active document no longer contains the Google Analytics runtime;
- no contact-form field contents are sent by this implementation.

## Activation

Create a GA4 Web data stream for:

`https://datac0re.is-a.dev/`

Then edit `site.config.json`:

```json
"analytics": {
  "provider": "ga4",
  "enabled": true,
  "measurementId": "G-XXXXXXXXXX",
  "consentMode": "basic",
  "consentStorageDays": 180
}
```

The shared `assets/js/language-routes.js` bootstrap loads the analytics runtime on all canonical EN / FR / ES pages, including future pages generated by the normal localization pipeline. Legacy `/en/...` redirect-only pages do not load analytics.

## GA4 property settings

Recommended for this portfolio:

1. Keep Enhanced Measurement enabled for standard page and outbound-link measurement.
2. Do not enable Google Signals or advertising personalization for this use case.
3. Link the GA4 property to the existing Google Search Console property once data is flowing.
4. Register these event-scoped custom dimensions if you want the additional best-effort source hint visible in normal GA4 reports:
   - `origin_type`
   - `origin_source_hint`
   - `origin_medium_hint`
   - `origin_campaign_hint`
   - `referrer_host`

GA4's standard Session source / medium remains the primary acquisition report.

## Validation

The pull-request workflow `Analytics privacy safety check` verifies:

- JavaScript syntax;
- GA4 cannot be enabled without a valid `G-` measurement ID;
- consent mode stays basic;
- all Google storage defaults start denied;
- advertising and Google Signals remain disabled;
- all canonical sitemap URLs load the shared bootstrap;
- `/en/...` compatibility redirects do not run analytics.
